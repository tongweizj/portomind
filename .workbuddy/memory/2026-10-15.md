## 调研中发现的关键事实（后续复用）

- **三进程架构**：client(Vite SPA) / server(Express API + 内嵌调度) / cron-worker(独立调度 Worker)，server 与 cron-worker **共享同一 MongoDB**；`SCHEDULER_ENABLED=true` 全局只能有一个进程。
- **调度双份实现**：`server/tasks/*` 与 `cron-worker/src/tasks/*` 并存且能力已分化——cron-worker 独有东财 fetcher、交易日历(calendar.service + config/markets)、开市 skip 校验、p-limit 并发、指数退避重试、完整性检查(integrityCheck)。
- **枚举三份复制**：`ASSET_*` 常量在 server / cron-worker / client 各存一份，改动需三向手工同步。
- **核心业务引擎为纯函数**：`positionCalculator.js`（移动平均成本、不访问 DB/不做汇率）、`thresholdChecker.js`、`suggestionGenerator.js`（先卖后买）、`assetClassAggregator.js` 均为纯函数。
- **两处关键保守原则**：缺价时估值字段为 `null` 不按零价误算；家庭 RMB 折算「宁可少报不可错报」（任一桶缺价或缺汇率则该组合 cnyValue 为 null 且不计入总额）。
- **硬约束**：AUTO 再平衡只生成建议 + 提醒，绝不自动交易（executeRebalance 强制 mode=MANUAL）。
- **前端遗留**：`pages/Portfolio/Basic.jsx`、`TargetAllocation.jsx` 未挂载路由；`MainLayout.jsx`、`common/ErrorAlert.jsx`、`common/Loading.jsx`、`utils/formatters.js`、`helpers.js`、`chartConfig.js` 均为 0 字节空文件。

### 整改中新发现：调度覆盖缺口（Q10，重要）

`SCHEDULER_ENABLED` 要求全局唯一所有者，**但两侧调度器任务集合不同**：

| 任务 | cron 变量 | server | cron-worker |
|---|---|:---:|:---:|
| 价格同步 | `PRICE_SYNC_CRON` | ✅ | ✅ |
| 完整性检查 | `HEALTH_CHECK_CRON` | ❌ | ✅ |
| 提醒评估 | `ALERT_EVAL_CRON` | ✅ | ❌ |
| 汇率同步 | `FX_SYNC_CRON` | ✅ | ❌ |
| 再平衡 AUTO | 按组合设置 | ✅ | ❌ |

→ **不存在能覆盖全部五类任务的单一进程**。默认拓扑（worker 持调度）下「提醒评估/汇率同步/再平衡 AUTO」不会自动运行；改由 server 持调度则「完整性检查」不会自动运行。处理：已在 OPERATIONS §3.1 / DEPLOY §3 / functions.md §2.2/§4.10.1/§9.2 / 两份 `.env.example` 如实写明，并给出两种拓扑切换步骤 + 手动触发入口（OPERATIONS §4）。**收口属代码改动，待用户决定**：把 alert/fx/rebalance 调度器补进 `cron-worker/src/schedulers/`。
