## 生产升级的三个真陷阱（本次分析结论，值得长期记住）

1. **`VITE_API_URL` 是构建时变量且当前值为 `http://localhost:8080/api`**（`client/.env` 与 `.env.example` 都是）。若照原样在生产构建，浏览器中的 `localhost` 指用户自己电脑 → 全站接口失效。生产必须置**空值**走同源 `/api`（`client/src/services/api.js:3-6` 空值回落 `/api`）+ Nginx 转发。
2. **SPA 的 `index.html` 不能被缓存**：Vite 产物是哈希文件名，但旧 index.html 引用旧哈希；若 Nginx 缓存 index.html 而旧 `assets/` 已被替换删除 → 白屏。需 index.html `no-cache`、`/assets/` 长缓存；升级后用户强刷一次。

## 生产环境现状（2026-10-25 发现，重要）

- 生产机 `MaxHomeServer` 的 `~/work/portomind/prod` **跑的是 `vite` dev server（5173），不是构建产物**：返回的 HTML 含 `@react-refresh` 与 `/src/main.jsx`，源码可直接被拉取。
- 本地电脑访问不了的真因：`client/vite.config.js` **没有配 `server.host`**，Vite 6 默认只监听 `localhost`（127.0.0.1/::1）。与防火墙无关（IP 访问不需配 `allowedHosts`，默认放行所有 IP）。
- 第二个坑：`client/.env` 的 `VITE_API_URL=http://localhost:8080/api` 在 5173 dev 模式下同样致命 —— 浏览器会打用户自己电脑的 8080；dev 模式应置空走同源 + `server.proxy`（已配 `VITE_API_PROXY_TARGET`，默认 `http://127.0.0.1:8080`）。
- Vite 6.4.4 事实：`preview.host` 默认继承 `server.host`；`preview.proxy` 默认继承 `server.proxy` → 用 `vite preview --host 0.0.0.0` 可零配置复用代理，是「不装 Nginx」时的折中方案。
