## 新增开发工具：`scripts/sync-db.cjs` 真实库 → 开发库整库镜像

**动因**：开发验收时开发库是空的（Reviewer 今天也遇到「`.env` 连的库没有交易数据，列表为空」），界面上的占比/图表/交易列表看不出真实效果。

**环境事实（实测）**：本机**没有** `mongodump`/`mongorestore`/`mongosh`；根 `node_modules` 有 `mongodb` 4.17.2 与 `dotenv` 16.6.1 → 用驱动自己搬，零新增依赖。两库同实例 `192.168.2.140:27017`，同凭据，只差库名。源库 12 集合 / 80,339 条（`prices` 79,911）；目标库 11 集合全空；无 validator、无 capped；索引 18 个。

**实现要点**：
- `scripts/sync-db.cjs` + 根 `package.json` 加 `"sync:db"`。参数：`--from/--to/--uri/--from-uri/--to-uri/--only/--exclude/--dry-run/--verify-only/--no-prune/--no-hash/--batch-size/--force`。
- 安全守卫（实测均返回退出码 1）：目标库名必须以 `_dev/_test/_e2e` 结尾（否则中止，`--force` 放行）；源=目标同名直接拒。
- 复制顺序：drop → **无条件 createCollection** → 分批 `insertMany`（2000/批）→ **最后建索引**（唯一索引先建会插入冲突）。
- 校验：集合清单 + 精确条数 + 排序后 `_id` 的 md5（≤30 万条时）。

**踩到并修掉的两个自身缺陷（都属「断言/实现假通过」）**：
1. 只在有集合选项时才 `createCollection` → 空集合且无索引的（源库 `portomind`、`test`）**从未被创建**，目标库只有 10 个集合，而条数校验用 `countDocuments` 对不存在的集合返回 0 → **误判通过**。修法：无条件创建 + 校验增加「集合清单」比对。
2. `--only` 模式下校验拿全库目标集合比对子集 → 误报「多出 11 个集合」。修法：`--only` 时不算多出。

**能失败的证据**：删掉开发库 1 条交易 → `--verify-only` 输出 `transactions 源=50 开发=49 ✗`、退出码 **1**；重同步后恢复 ✓。不是只看绿灯。

**结果**：全库镜像完成，12 集合 / 80,339 条 / 索引数逐一相等 / 抽样交易整条文档 `JSON.stringify` 完全相等 / 开发库价格区间 2020-01-02 ~ 2026-10-19。

**文档**：`docs/manual/DEPLOYMENT.md` 新增 **§5.5**（单一归属，别处不重复）。`MEMORY.md` 更正「MONGO_URI 主机不可达 / 开发库为空」这条已过时的事实。

## 修正：改用官方 mongodump/mongorestore 做复制引擎（Max 指出「可以装的」）

**我的失误**：上一版默认「本机没有 MongoDB Database Tools → 用驱动自己搬」，但没先问就绕开了官方工具。Max 一句「mongodump 可以装的」直接推翻这个前提。

**安装**：`scoop install mongodb-database-tools` → 100.14.0（服务端 MongoDB 8.0.32，兼容）。⚠️ scoop 清单**未声明 bin，不生成 shim**，`mongodump` 不在 PATH；实际路径 `C:/Users/maxto/scoop/apps/mongodb-database-tools/current/bin/`。

**性能对比（同一份 80,339 条数据）**：官方工具 dump 1.2–1.6s + restore 2.5–2.9s；自写驱动搬运约 4s（且只覆盖复制，不含校验）。gzip 归档仅 946 KB。

**架构调整（避免两份复制实现并存——本项目明确的纪律）**：删除 `scripts/sync-db.cjs` 里全部手写搬运代码，改为：
- 复制引擎 = `mongodump --gzip --archive=<tmp>` → `mongorestore --nsFrom/--nsTo/--nsInclude/--drop`；
- 脚本只保留官方工具**没有**的两件事：**安全守卫**（目标库名必须 `_dev/_test/_e2e`；源=目标拒绝；官方工具灌错库零提示）与**事后校验**（集合清单 + 精确条数 + **索引清单** + `_id` 哈希）。
- 工具定位：env `MONGODUMP_BIN`/`MONGORESTORE_BIN` → PATH → scoop 默认目录 → 报错并给安装命令。
- 临时归档写 `os.tmpdir()`，`finally` 里删除（实测无残留）。

**踩到的 3 个官方工具坑（都已修，且都值得记住）**：
1. **参数必须 `--opt=value`**：`--uri mongodb://…`、`--archive <path>` 会被当成**位置参数** → 报 `provide only one MongoDB connection string`。我手工测试时恰好都写了 `=`，所以第一次封装才暴露。
2. **`--nsFrom/--nsTo` 必须配 `--nsInclude`**：只给前两者 → `0 document(s) restored successfully`，**退出码仍是 0**（典型的静默假成功）。现已加「还原条数 vs 源库统计」一致性告警兜底。
3. **还原统计写在 stderr**：只 grep stdout 会把条数解析成 `?`。现改成 `out + err` 合并匹配，并额外解析 `N document(s) failed`。

**验证结果**：新引擎跑完 → 12 集合 / 80,339 条 / 索引清单完全一致（含 `prices.symbol_1_timestamp_1`、`taskName_1_runKey_1` 两个唯一索引）/ `_id` 哈希逐个相等 / 退出码 0。守卫回归：`--to portomind_prod` 与源=目标均返回 1；`--exclude prices,taskruns` → 10 集合 224 条；`--only nosuchcol` 报错退出。

**文档**：`DEPLOYMENT.md §5.5` 重写（原文「无需 mongodump」已失效），补安装命令、引擎说明、守卫与校验口径、以及 `--opt=value` 这个坑。`MEMORY.md` 同步更正。
