# cron-worker 产品介绍

> 受众：**使用者 / 产品**。
> 本文**不是产品需求文档（PRD）**——不写需求、验收、范围、优先级。它只是对 cron-worker 这 5 个后台任务的
> **功能介绍**：每个任务解决什么问题、跑出什么结果、对你（使用者）意味着什么。
>
> - 如何安装 / 启动 / 手动触发 / 监控排障见 [运维手册](./CRON_WORKER_OPS.md)；
>   调度如何实现见 [开发文档](../dev/CRON_WORKER_DEV.md)。
> - 这些任务都属于「家庭投资组合监控」整体产品，界面上能看到的结果（再平衡建议、提醒、汇率显示等）
>   由 [client 使用手册](./CLIENT.md) 讲述。

## 1. 为什么需要这个进程（一句话定位）

PortoMind 的价格、汇率、提醒、再平衡建议都不是你每次打开页面才去算的——它们由 cron-worker 在后台
**按时间表自动跑**。你打开界面看到的「今日行情」「再平衡建议」「提醒通知」，背后都是这个进程定时产出的结果。
它是整个产品的「数据更新引擎」，只是没有界面、不直接对你说话。

## 2. 五大定时任务功能介绍

| # | 任务 | 默认时间 | 解决什么问题 | 产出什么 |
|---|---|---|---|---|
| 1 | 价格同步 | 03:00 | 你持有的基金 / ETF 每天都有新净值，需要自动采集入库 | 每个激活资产当天的最新价写入 `Price` |
| 2 | 完整性检查 | 03:30 | 万一某天价格没采到（上游缺数 / 网络抖动），数据会出现缺口 | 比对「应有 vs 实有」价格，发现缺口并自动回补 |
| 3 | 提醒评估 | 04:00 | 你设的提醒规则（涨跌幅 / 估值分位 / 分红等）需要每日判断 | 命中规则时产生提醒事件，前端通知你 |
| 4 | 汇率同步 | 09:30 | 跨币种组合（加币 / 美金 → 人民币）需要当日汇率才能统一折算 | USD / CAD / HKD → CNY 的当日汇率入库 |
| 5 | 再平衡分发 | 00:00 | 你为每个组合设的再平衡频率（每日 / 每周一 / 每月 1 日）需要到点检查 | 到期组合生成再平衡建议 + 提醒（**只建议，不自动交易**） |

> 五项任务的触发时间、周期都可在 `cron-worker/.env` 调整；详细机制见 [开发文档](../dev/CRON_WORKER_DEV.md)。

### 2.1 价格同步（每日 03:00）

自动遍历你标记为 `active` 的所有资产，逐个确认其所属市场当天是否开市（含周末与法定节假日），开市才采集、
休市跳过。单个资产采集失败不影响其余。**同一天重复跑不会产生重复价格**（幂等入库）。

对你意味着：每天早上醒来，组合里的基金净值通常已经是「前一天收盘」的最新值。

### 2.2 完整性检查（每日 03:30）

它回答一个问题：**「每支基金理论上该有多少天价格，实际采到了多少？」**
依据每支资产的 `launchDate`（成立日）和市场推算「应有交易日数」，再与实际落库记录数比对。
发现缺口时默认自动调历史回补补上，并把缺口区间合并成报告。

对你意味着：数据质量有兜底——偶尔漏采的价格会被自动发现并补回，你看到的曲线更完整。

### 2.3 提醒评估（每日 04:00）

对你设置的每一条提醒规则（例如「某基金回撤超过 X% 提醒我」「估值分位低于 Y 提醒我」）逐条评估，
命中的就产生一条提醒事件，前端据此通知你。**没有数据或规则静默不触发**，不会误报。

### 2.4 汇率同步（每日 09:30）

采集 USD / CAD / HKD 兑 CNY 的当日汇率。因为你的组合里有加币、美金资产，要把它们统一折算成人民币展示，
就必须有当日汇率。采集失败不阻塞系统，缺口时可手动录入（见 [client 使用手册](./CLIENT.md) 与
[server 使用手册](./SERVER.md) 的手动汇率录入）。

### 2.5 再平衡分发（每日 00:00）

这是最「智能」的一项。你给每个组合设了再平衡频率（每日 / 每周一 / 每月 1 日），进程每天零点扫描所有组合，
判断今天是否到再平衡日；到期就做阈值检查，生成一份**再平衡建议**并提醒你。

**重要不变量**：无论设置什么频率，AUTO 再平衡**只生成建议 + 提醒，永不自动交易**。
是否执行买卖，永远由你（或你在界面上确认）决定。改再平衡频率**无需重启**进程，下一个零点周期自动生效。

## 3. 数据质量程序功能介绍

这三项（价格同步 / 完整性检查 / 历史回补）共同保证「你看到的价格数据是对的、齐的」。

### 3.1 价格同步

见 §2.1。核心能力是「自动、按市场开市、故障隔离、幂等」地采集最新价。

### 3.2 完整性检查

见 §2.2。核心能力是「自动发现价格缺口并回补」。它有三个关键状态你需要知道：

- `OK`：这支基金价格完整，无需处理；
- `GAP`：存在缺失交易日，已（或应）自动补全；
- `SKIPPED_NO_LAUNCH_DATE`：这支基金没填「成立日」（`launchDate`），系统无法推算应有天数，被跳过——
  这意味着它**不参与完整性核对**，需要你补上成立日（见 §3.4）。

自动回补有安全边界：默认只补「最近 30 天」内的缺口，更早的缺口延后处理，避免首次运行一次性回补过大。
全量历史回补请用 §3.3 的显式命令。

### 3.3 历史回补

当你需要补齐一段较长时间的历史价格（例如新接入一支基金、或一次性补多年数据），用显式的历史回补命令，
可指定起止日期、指定符号、控制并发。它和每日价格同步共用同一采集逻辑，**幂等**，跑过的不会重复写。

### 3.4 `launchDate`（成立日）的作用

完整性检查靠「成立日」推算一支基金「理论上该有多少交易日」。如果一支基金没填成立日，它会被
`SKIPPED_NO_LAUNCH_DATE` 跳过、不再被完整性核对覆盖。因此：**想让某支基金纳入数据质量保障，记得补成立日。**
目前成立日尚未在界面暴露，需要通过数据库或 API 维护（具体方式见 [开发文档 §6](../dev/CRON_WORKER_DEV.md#6-launchdate-字段与暴露)）。

## 4. 你（使用者）需要关心什么

- **再平衡建议什么时候出现**：取决于你给组合设的频率（每日 / 每周一 / 每月 1 日），由 §2.5 的分发产生。
- **提醒从哪里来**：你设的规则由 §2.3 每日评估，命中即通知。
- **汇率显示准不准**：取决于 §2.4 每日 09:30 采集；异常时可手动录入。
- **看到的价格曲线是否完整**：由 §2.1 + §2.2 自动保障；个别基金若长期缺数据，多半是没填成立日或上游缺数。
- **你永远不需要手动跑这些任务**——它们全自动。手动触发入口（CLI / 界面按钮 / API）只在运维排障或补数据时用到，
  详见 [运维手册 §6](./CRON_WORKER_OPS.md#6-命令行手动入口) 与 [client 使用手册](./CLIENT.md)。
