## 0. TL;DR

把客户端当前两个互相割裂的顶层频道——**资产管理**（基本属性设置）与**价格**（每日表现跟踪）——重组为**以「标的」实体为中心**的信息架构：

- **顶层「自选行情」（原价格监控面）**：跨资产、只读、快进快出；富化资产名、涨跌幅、大类；带工具栏（搜索 + 关注/大类过滤）与**数据缺口标红（≥3 天未更新）**；屏底「查看所有标的 →」按钮进入标的列表。
- **「标的列表」（原资产管理）移出顶层导航**：低频配置不应占导航位，改为「自选行情」屏内入口；保留增删改、状态、多选（为 P2 批量分类预留）。
- **「标的详情页」**：单品深挖页面，把"基本属性 + 价格表现"同屏，采用「**属性收进标题区 + 价格表现全宽面板**」结构（OQ3 已决：B 版，不做左右两栏分栏）。

**关键判断**：合并应发生在「实体层面」（详情页把属性与表现合一），而非「任务层面」（把低频配置和高频监控揉进同一页）。直接拼成一页会牺牲每日盯盘体验。

## 1. Problem Statement

**用户问题**：在 PortoMind 客户端，一个标的的"它是什么"（基本属性）和"它每天表现如何"（价格）被拆成了两个互不相干的顶层导航项。用户要理解单个标的，必须在「资产管理」和「价格」之间反复跳转；而每日盯盘时，价格频道只暴露 `symbol / price / 时间戳`，连资产名和涨跌幅都没有，像一个脱离上下文的裸数据转储。同时，「资产管理」作为低频配置入口却长期占用顶层导航，导航拥挤且语义重叠。

**谁遇到、多频繁**：Max（家庭投资组合 owner，每日盯盘 + 偶发配置）与童玮。盯盘为**每日高频**，配置为**偶发低频**。

**证据（来自代码与产品文档）**：
- `client/src/components/layout/Sidebar.jsx`：导航项为 8 个独立顶层频道，`价格` 与 `资产管理` 并列，互无归属。
- `client/src/pages/Prices/Today.jsx`：`Today` 仅渲染 `symbol / price / timestamp`，无资产名、无涨跌幅、无组合上下文——证实"价格频道孤立且 raw"。
- `client/src/pages/Asset/AssetList.jsx`：资产表的"价格"动作与代码链接都跳去 `/prices/:symbol/history`，说明两个频道在概念上已是同一标的的两面，只是被硬拆。
- `client/src/pages/Dashboard.jsx`：首页是"提醒中心"，**不具备跨资产行情总览**。因此跨资产每日监控入口**只有**价格频道一个——它一旦被并入配置页，盯盘入口即丢失。
- 产品文档呼应：`PL-2-market-data` 的 `AS-07`（数据缺口可见）、`USER_RESEARCH` 的 `H-02`（资产缺批量分类 → 大类目标/再平衡无法真正好用）都指向"资产与价格应当更紧密地同框"。

**不解决的代价**：导航认知负担（8 项里两个频道语义相邻却分立，且低频配置占用高频导航位）、价格频道长期处于"半成品"状态、单品认知需跨页拼接、数据可信度（缺口）不可见。

## 2. Goals

- **G1（用户）单一事实来源可视**：每个标的都有唯一详情页，同时呈现基本属性与每日表现；从自选行情任一处均可到达，标的列表入口位于自选行情屏内。
  - *判定*：标的详情页上线，自选行情的标的数据行可跳转详情；自选行情屏底「查看所有标的」入口可达列表。
- **G2（用户）每日盯盘不被稀释**：跨资产"自选行情"保留为一眼扫完所有持仓的快视图，且带资产名、涨跌幅、大类；低频配置不再占用顶层导航。
  - *判定*：自选行情含名称 + 涨跌幅 + 大类；导航由 8 降为 **7** 项，原资产管理入口内聚于自选行情。
- **G3（用户）数据可信**：价格缺口可见（"N 天未更新"并标红，阈值 **≥3 天**）。
  - *判定*：自选行情与详情页均展示最近更新时间，超过 3 天标红（呼应 `AS-07`）。
- **G4（产品）导航语义收敛**：价格不再作为"孤立频道"存在，而是标的实体下的"表现"面；消除两个频道的割裂感，并把低频配置收进高频屏。
  - *判定*：导航中不再有独立语义重叠的"价格"项，且"资产管理"不再作为顶层项。

---

## 3. Non-Goals

- **NG1 不改服务端数据模型 / 采集管线**：本方案仅涉及客户端信息架构与页面；行情采集、估值分位、cron-worker 调度均不在范围内。
- **NG2 不新增资产类型或行情数据源**：不扩展 `ASSET_TYPES` / 市场接入。
- **NG3 不合并交易记录 / 组合管理 / 家庭视图**：只动资产管理 + 价格两条线。
- **NG4 不引入认证 / 登录**：属 PL-0 独立 P0（且文档明确"公网前才需要"），与此 IA 无关。
- **NG5 不做组合级分析重构**：组合洞察、再平衡建议保持现状。

## 4. Proposed Information Architecture

### 4.1 导航变更（最终：7 项）

| 现状（Sidebar 8 项） | 建议（最终） |
|---|---|
| 价格（独立顶层） | → **自选行情**（监控面·带「监控」badge·含标的列表入口） |
| 资产管理（独立顶层） | → **移出顶层导航**，收敛为「自选行情」屏内「查看所有标的 →」入口（低频配置） |
| Dashboard · 提醒 / 组合管理 / 交易记录 / 家庭视图 / 提醒规则 / 日志 | 不变（位置微调：Dashboard·提醒置顶，加「总览」分组标签） |

**最终 Sidebar（7 项 + 「总览」分组标签）**：
```
总览
├ Dashboard · 提醒
├ 组合管理
├ 自选行情    ←  active，badge「监控」
├ 交易记录
├ 家庭视图
├ 提醒规则
└ 日志
（原「资产管理」以 removed-note 标注：已移出导航，收敛为自选行情内入口）
```

> 说明：导航项由 8 降为 **7**。若后续决定将自选行情并入 Dashboard 标签页，可进一步降到 6 项（见 OQ2）。
>
> ⚠️ **2026-10-27 演进注记**：此后「家庭视图」已下线（`FS-household-view-split`），「提醒规则」又移出侧栏改由顶栏下拉进入（Human 指令）。**当前侧栏 = 4 项**：Dashboard / 组合管理 / 自选行情 / 日志；本树仅供追溯。

### 4.2 路由映射（最小化改动）

| 路由 | 现状 | 建议 |
|---|---|---|
| `/assets` | AssetList（顶层导航进入） | → `/instruments`（标的列表，**从自选行情屏底「查看所有标的」入口进入**，不再由 Sidebar 直达） |
| `/assets/new` · `/assets/edit/:id` | AssetForm | → `/instruments/new` · `/instruments/edit/:id`（复用） |
| **`/instruments/:id`（新增）** | — | **标的详情页**（标题区属性 + 价格表现面板） |
| `/prices` | Today（裸数据） | 自选行情（富化：名称 + 涨跌幅 + 大类 + 工具栏 + 缺口标红 + 跳详情 + 屏底列表入口） |
| `/prices/:symbol/history` | History | 保留，从详情页「查看完整历史」进入 |

### 4.3 标的详情页（核心新增）

单品深挖页面，采用「**属性收进标题区 + 价格表现全宽面板**」结构（OQ3 已决：B 版，不做左右两栏卡片分栏）：

- **标题区（基本属性内联）**：标的名称（大标题）+ 一行 meta = `代码 · 市场 · 币种 · 类型 · 大类 · 标签`（停用标的追加 `· 已停用`）。右侧「编辑属性」按钮（跳转现有 AssetForm `/instruments/edit/:id`）。
- **价格表现面板**（全宽，置于标题区下方）：
  - 今日价（大字）、当日涨跌幅（标注「按币种计，不跨币汇总」）；
  - 近 30 日迷你走势 sparkline（R7）；
  - 完整历史走势图（复用现有 History 组件，链接 `/prices/:symbol/history`）；
  - 空态「暂无价格记录」（遵循共享内核"缺价不按零价"原则，不显示 0 价误算）。

> 注：本布局**不做左右两栏卡片分栏**——基本属性收进标题区作为上下文，价格表现占据全宽面板，最大化走势图可用宽度。

## 5. User Stories

1. **US1（每日监控者）**：作为每日查看持仓的人，我希望有一个"自选行情"页一次性列出所有持仓的今日价、涨跌幅、大类，并可搜索/过滤，以便一眼扫完、无需逐个打开。
2. **US2（账本维护者）**：作为维护投资账本的人，我希望每个标的详情页把"基本属性"（收进标题区）与"价格表现"（全宽面板）放在同一屏看。
3. **US3（数据可信诉求者）**：作为用户，我希望看到某标的"最近更新：N 天前"，且 ≥3 天未更新标红，以便判断数据是否过期、决定是否信任。
4. **US4（下钻者）**：作为用户，我希望在自选行情点击某个标的即可进入它的详情（属性 + 完整历史），以便快速调查异常。
5. **US5（配置者）**：作为账本维护者，我希望在自选行情屏内能经「查看所有标的」进入列表做增删改（低频配置），但不希望它占用日常顶层导航。
6. **边界 US**：
   - 标的**无价格历史**（刚添加）：表现区显示空态"暂无价格记录"，不报错、不显示 0 价误算。
   - 标的**已停用（active=false）**：自选行情默认隐藏或置灰（详情页 header 标「已停用」仍可读）。
   - **多币种**标的：涨跌幅按各自币种计算，不做跨币汇总（遵循"家庭 RMB 折算宁可少报不可错报"）。
   - **空标的列表 / 空行情**：自选行情显示空态，引导「去添加标的」（经列表入口）。

## 6. Requirements

### P0 — Must Have（不交付则方案不成立）

- **R1 导航重命名、重定向与层级调整**
  - 顶层导航 `价格` → `自选行情`（带「监控」badge）；删除顶层 `资产管理` 项，将其作为「自选行情」屏内入口（屏底「查看所有标的 →」按钮）。
  - Sidebar 7 项（含「总览」分组标签，Dashboard·提醒置顶）。
  - 旧路由 `/assets`、`/assets/edit/:id` 重定向到 `/instruments` 对应路径（避免书签/历史失效）。
  - *验收*：侧边栏显示 7 项且无「资产管理」顶层项；自选行情屏底可见「查看所有标的」入口；旧 `/assets` 自动跳转新路径。
- **R2 标的列表页 `/instruments`（从自选行情进入）**
  - 列：全选框 / 代码 / 名称 / 市场 / 币种 / 类型 / 大类 / 标签 / 状态(关注·启用·已停用) / 操作(编辑·删除)。
  - 顶部「＋ 添加标的」按钮（复用 AssetForm）；多选框为 P2 批量分类（R11）预留。
  - **移除原「价格」行动作**（价格改由自选行情 / 详情查看）。
  - *验收*：列表含状态列与多选框；编辑/删除/添加可达；行内无冗余「价格」动作。
- **R3 自选行情富化（`/prices`）**
  - 在现有 `Today` 基础上补：资产名称、当日涨跌幅、大类 chip；每行可点击进入标的详情。
  - **屏内工具栏**：按名称/代码搜索 + 按关注过滤（仅关注/含未关注）+ 按大类过滤（股票/债券/商品/现金）（呼应 R8）。
  - 屏底「查看所有标的 →」按钮进入 `/instruments`。
  - Topbar 展示「标红阈值 ≥3 天未更新」pill（呼应 R6 / OQ4）。
  - 复用既有 `getTodayPrices` / `getPricesByDate`，**不新增服务端接口**。
  - *验收*：自选行情含名称 + 涨跌幅 + 大类；点击行进详情；屏底可到列表；搜索/过滤生效；缺口 ≥3 天标红。
- **R4 新增标的详情页 `/instruments/:id`**
  - **标题区**展示基本属性（代码/市场/币种/类型/大类/标签，停用追加已停用）+「编辑属性」入口。
  - **价格表现面板**：今日价 + 当日涨跌幅(按币种) + 近 30 日 sparkline + 历史图表（复用 `getPriceHistory` / 现有 History 渲染）+ 空态。
  - *验收*：进入任一标的详情，属性与表现同屏可见；编辑入口可达；无价格历史时表现为空态而非报错。
- **R5 复用既有数据接口，零服务端改动**
  - 仅用 `getAssets` / `getTodayPrices` / `getPricesByDate` / `getPriceHistory` / `deleteAsset`，不触碰 `shared/` 内核。
  - *验收*：本方案不修改任何 server / shared / cron-worker 文件。

### P1 — Should Have（显著提升，可快速跟投）

- **R6 数据缺口可见（呼应 AS-07）**：自选行情与详情页展示"最近更新：N 天前"；≥3 天标红（OQ4 已决）。*验收*：过期标的在自选行情中标红提示（"N 天前 · 缺口"）。
- **R7 表现区 sparkline**：详情页与自选行情行内展示近 30 日迷你走势。*验收*：有历史数据的标的可见走势线。
- **R8 自选行情筛选/搜索**：已实现于 wireframe 工具栏（搜索 + 关注/大类过滤）；验收口径与标的列表一致。*验收*：过滤与搜索生效。

### P2 — Future（v1 之外，但设计要留余地）

- **R9 详情页内联编辑属性**：不跳转独立 AssetForm，直接在详情页编辑（需设计表单承载）。*设计约束*：详情页布局须预留编辑区。
- **R10 自选行情并入 Dashboard 标签页**：使导航降到 6 项。*设计约束*：自选行情组件须可独立复用为 Dashboard 的一个 tab。
- **R11 标的批量分类（呼应 H-02）**：在标的列表提供批量设置大类。*设计约束*：列表已支持多选框，R2 已预留。

## 7. Success Metrics

> 注：本应用为自托管、样本极小（n=2 用户），以下指标为**方向性**参考，非统计显著。

**领先指标（上线后数日~数周）**
- 价格查看入口集中度：自选行情 + 标的详情承接的"看价格"行为占比 → 目标 30 天内 ≥ 80%。
- 导航精简收益：顶层项由 8 降 7，资产管理相关低频点击不再占用日常导航曝光。
- 单品认知跳转次数：从资产管理跳价格 / 反之的跨页跳转下降（代理指标：详情页 PV 上升、跨频道导航 PV 下降）。
- 缺口发现率：标红缺口（≥3 天）被用户"看到并反馈/处理"的比例。

**滞后指标（数周~数月）**
- 数据信任度：用户对"价格是否可信"的主观评分。
- 盯盘耗时：每日扫读全部持仓所需时间（目标不增）。

**评估时点**：上线后 1 周（领先）、1 个月（滞后初评）。

## 9. Timeline / Phasing

单版本可交付，纯客户端改动，工作量小。

- **Phase 1（P0）**：导航重命名 + 层级调整（资产管理移入自选行情）+ 重定向；新增标的详情页（R4）；自选行情富化（名称 + 涨跌幅 + 大类 + 工具栏 + 缺口标红 + 屏底列表入口）；标的列表页（R2）。预计 1 个迭代。
- **Phase 2（P1）**：缺口可见（R6）+ sparkline（R7）+ 筛选搜索（R8，wireframe 已含控件）。
- **Phase 3（P2）**：内联编辑（R9）、Dashboard 标签页合并（R10）、批量分类（R11）按优先级择机。

## 10. Dependencies & Risks

- **依赖**：现有 `asset.service.js`、`price.service.js` 接口稳定；`AssetForm` / `History` 组件可复用。无跨进程依赖。
- **风险 R1（监控被稀释）**：若误把配置与监控拼成一页 → 盯盘体验塌掉。**缓解**：严格按本方案"实体层合一、任务层分离"执行，自选行情独立保留且承载列表入口。
- **风险 R2（命名混淆）**：「投资品 / 资产管理 / 资产 / 标的」多词易混 → 本次已锁定「标的」一词，UI 文案统一。
- **风险 R3（重定向遗漏）**：旧书签/历史失效 → 用 R1 重定向覆盖。
- **风险 R4（低频入口藏太深）**：资产管理移出导航后，配置者找不到入口。**缓解**：自选行情屏底以「查看所有标的 →」按钮呈现，并在空态/引导中明确指向。
- **风险 R5（详情布局反复）**：前期在"左右分栏"与"header+面板"间摇摆。**缓解**：OQ3 已决（B 版：属性收进 header + 表现全宽，不做左右分栏），R4 按此实现即可，不再返工。
