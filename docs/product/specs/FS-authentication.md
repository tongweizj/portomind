# Feature Spec — 账号与访问控制（用户模块）

> 版本：v1.0 · 日期：2026-10-26 · 状态：**Approved（产品形态已由 Human 裁决，见 §12）**  
> 关联：[PL-0 平台基座](../lines/PL-0-platform-foundation.md)（本能力归属 `M0.2d`）· [ADR-001](../../architecture/adr/ADR-001-authentication.md)（技术决策）· [DEPLOYMENT §9](../../manual/DEPLOYMENT.md)（安全边界，实施后同步）  
> 行号与文件事实以 2026-10-26 工作树（`main`）为准；与代码不符时以符号名为准。

## 0. TL;DR

PortoMind 目前**没有任何认证**：任何人访问 IP 即可看到全部家庭资产。本 FS 确立一个**多账号、单租户**的访问控制模型：

- **不做自助注册**。账号只能由管理员创建。
- **所有账号共享同一份家庭数据**（不引入 `tenantId` / `ownerId`，10 个业务模型零改动）——它不是多租户 SaaS，而是"一个家庭的多个人共用一个账本"。
- 两种角色：`admin`（业务全读写 + 用户管理）、`member`（业务全读写，不能管理用户）。
- 用户**不可删除，只能停用**；系统必须始终至少有一个启用状态的 `admin`。
- 首次部署自动生成 `admin / admin`，**首次登录强制改密**。

一句话边界：**要的是"谁在用这个系统"，不是"谁的数据"**。

## 1. Problem Statement

### 1.1 现状：零防护，但界面承诺了防护

| 层面   | 事实                                                                                                                                                          |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API  | 9 个路由全部裸奔（`server/app.js:41-49`），无任何鉴权中间件                                                                                                                   |
| CORS | `app.js:34` 用 `cors({ origin: true })`——**任意来源都接受**。`app.js:21-24` 确实读了 `CORS_ORIGINS` 构造出 `allowedOrigins`，但使用它的白名单 `cors()` 整段被注释（`:26-33`）→ **变量读了，没生效** |
| 前端   | `components/layout/Sidebar.jsx` 底部渲染「退出登录」按钮，**无 onClick、无登录态**                                                                                             |
| 决策   | `docs/architecture/adr/ADR-001-authentication.md` 是**空模板**，标题仍是 `ADR-XXX — <Decision Title>`                                                                |
| 文档   | `docs/readme.md` 曾引用 `product/specs/authentication.md`——**该文件从未存在**（死链已记入文档债）                                                                               |

### 1.2 真正的风险不是"没做"，是"看起来做了"

无认证本身在纯内网尚可接受。但界面上有一个「退出登录」按钮，会让使用者确信"系统有账户体系、别人进不来"，而实际上任何人拿到 IP 就能看到全家庭资产、改交易、删组合。**假的安全感比没有安全感更危险**。

### 1.3 一旦暴露公网，单日即可被扫

家宽/公网 IP 上的未认证 API 通常在被暴露后数小时内被扫描器命中。而本产品**明确记录了公网是既定方向**（`PRODUCT_LINES.md` 阶段表把"公网前完成认证"列为待办），因此这不是可选项。

### 1.4 缺一个"多人共用一本账"的形态

当前家庭由两人共同维护（CN 三个组合 + 家庭层），实际使用中"这笔是谁录的""谁能改目标配置"没有承载。**本期只解决身份与准入，不解决操作留痕**（见 §3 Non-Goals）。

## 2. Goals

| #  | 目标                        | 判定                   |
| -- | ------------------------- | -------------------- |
| G1 | 未认证请求无法访问任何业务接口           | 全部业务路由返回 401         |
| G2 | 首次部署开箱可用，无需改配置即可登录        | 自动生成 `admin / admin` |
| G3 | 默认口令不会长期驻留                | 首次登录强制改密             |
| G4 | 管理员可创建、停用、重置其他账号          | 系统设置页可用              |
| G5 | 每个账号可自助改用户名与密码            | 账户页可用                |
| G6 | 系统不会因误操作失去管理能力            | 至少一个启用 `admin` 的守护   |
| G7 | CORS 从"全开"收敛为白名单，且与认证同批上线 | 跨站请求被拒               |

## 3. Non-Goals

| #   | 不做                         | 理由                                                                      |
| --- | -------------------------- | ----------------------------------------------------------------------- |
| NG1 | **自助注册**                   | 注册意味着陌生人可创建身份。本产品的账号是"家庭成员"级别的授予行为，只能由管理员发起                             |
| NG2 | **多租户 / 账号级数据隔离**          | 所有账号共享同一份家庭数据。加 `tenantId` 要给 10 个模型全加字段、改造全部查询、重新定义 PL-6 家庭层——那等于换一个产品 |
| NG3 | **邮箱/手机找回密码**              | 单机自托管、无邮件通道。"忘记密码"的真实形态是运维动作（管理员重置 或 DB 直改），不是功能                        |
| NG4 | **操作人留痕（`createdBy` 等）**   | 需要给 PL-1 全链路（交易/导入/再平衡执行）加字段与展示，工作量与本模块相当。本期只记 `lastLoginAt`，业务留痕另立项    |
| NG5 | 角色细分（只读成员、按组合授权）           | 先做 `admin` / `member` 两角色，`role` 用枚举留扩展位。真实需求出现再加 `viewer`              |
| NG6 | 第三方登录（OAuth / 微信 / GitHub） | 单家庭场景无收益                                                                |
| NG7 | 密码找回令牌、双因素认证               | 与 NG3 同理，超出"能用且不假"的标准                                                   |
| NG8 | 用户删除                       | 只停用。删除会引出"历史归属"与"最后一个 admin"两个坑                                         |

## 4. 产品形态

### 4.1 首次部署

| 项    | 行为                                                          |
| ---- | ----------------------------------------------------------- |
| 触发条件 | 服务启动连库后，若 `users` 集合为空                                      |
| 结果   | 创建 `admin` / `admin`，`role=admin`，`mustChangePassword=true` |
| 日志   | `AUTH_SEEDED_DEFAULT_ADMIN`（**不打印密码**）                      |
| 幂等   | 已有任意用户则跳过，不重置、不覆盖                                           |
| 登录页  | **不提示**默认账号。首次部署流程写入 `DEPLOYMENT.md`，不写在登录页上                |

### 4.2 首次登录强制改密（G3）

登录成功后，若 `mustChangePassword=true`：

- 除「改密码」「登出」「查询当前会话」外，**所有接口返回 403**，错误码 `PASSWORD_CHANGE_REQUIRED`；
- 前端直接进入账户页的改密表单，不显示"稍后再说"；
- 改密成功后 `mustChangePassword=false`，恢复全部权限。

同样的强制逻辑适用于：管理员新建账号、管理员重置他人密码（这两种情况下密码是"别人设定的"，必须由本人改成自己的）。

### 4.3 普通用户：账户页 `/account`

| 区块    | 内容                 | 规则                                  |
| ----- | ------------------ | ----------------------------------- |
| 身份    | 用户名、角色徽标、上次登录时间    | 只读                                  |
| 修改用户名 | 输入框 + 保存           | 唯一性校验；成功后当前会话保持有效，界面即时刷新            |
| 修改密码  | 当前密码 + 新密码 + 确认新密码 | 必须校验当前密码；成功后**该账号其他会话全部失效**（当前会话保留） |
| 退出登录  | 按钮                 | 清会话 → 跳 `/login`                    |

### 4.4 管理员：账户页 + 系统设置 Tab

管理员进入 `/account` 时，页内多一个 **「系统设置」Tab**（`/account/users`），**不新增侧栏顶级导航项**（侧栏已有 5 项，且这是低频管理功能）。

| 功能      | 行为                          | 约束                                     |
| ------- | --------------------------- | -------------------------------------- |
| 用户列表    | 用户名 / 角色 / 状态 / 上次登录 / 创建时间 | 按创建时间倒序                                |
| 新建用户    | 用户名 + 初始密码 + 角色             | 初始密码由管理员设定 → 该用户首次登录强制改密               |
| 停用 / 启用 | 切换 `active`                 | 不能停用自己；停用后该用户**现存会话立即失效**              |
| 重置密码    | 管理员设定新密码                    | 目标用户全部会话失效 + `mustChangePassword=true` |
| 改角色     | `admin` ↔ `member`          | **不能把最后一个启用 admin 降级**                 |
| 删除      | ——                          | **无此功能**（NG8），只停用                      |

**核心不变量**：任意时刻，`users` 中至少存在一个 `active=true && role='admin'` 的账号。破坏它的三条路径必须全部阻断：①停用 admin；②把 admin 降级为 member；③（不存在）删除 admin。

### 4.5 导航与登录态

- 新增路由 `/login`（**不套 `AppLayout`**，无侧栏/顶栏）；
- `/account`、`/account/users` 套 `AppLayout`，从侧栏底部用户区进入（**不占 5 个顶级导航位**）；
- 侧栏底部现有「退出登录」按钮**接上真实 handler**，并在其上方显示当前用户名 + 角色徽标；
- 未登录访问任何页面 → 重定向 `/login?next=<原路径>`；登录后回跳；
- 已登录访问 `/login` → 重定向 `/`；
- 任意接口返回 401 → 清空前端缓存 → 跳登录页（`next` 带上当前路径）。

## 5. 角色与权限矩阵

| 能力                         | `admin` | `member` |
| -------------------------- | :-----: | :------: |
| 查看全部资产 / 组合 / 交易 / 行情 / 提醒 |    ✅    |     ✅    |
| 新增 / 编辑交易、CSV 导入           |    ✅    |     ✅    |
| 新增 / 编辑 / 归档组合，配置目标与阈值     |    ✅    |     ✅    |
| 触发再平衡检查 / 生成建议 / 确认执行      |    ✅    |     ✅    |
| 提醒规则 CRUD、标记已读             |    ✅    |     ✅    |
| 查看日志 `/logs`               |    ✅    |     ✅    |
| 改自己的用户名 / 密码               |    ✅    |     ✅    |
| 查看用户列表、新建用户、停用、重置密码、改角色    |    ✅    |  ❌ (403) |

> 无"数据归属"维度：两个角色看到的是**同一份数据**。区别只在"能否管理账号"。

## 6. Requirements

### 6.1 P0 — 交付单元 U1：后端认证内核（`shared` + `server`）

| #      | 要求                                                                                                                                   |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| U1-R1  | `User` 模型：`username`（唯一、小写、3–32 字符）、`passwordHash`、`role`、`active`、`mustChangePassword`、`lastLoginAt`                                |
| U1-R2  | 密码哈希用 **bcrypt**（`bcryptjs`，cost 10）。禁止 md5/sha1/sha256 裸哈希                                                                          |
| U1-R3  | `Session` 模型：`sid`（唯一）、`userId`、`createdAt`（**TTL 过期**）、`lastSeenAt`、`ip`、`ua`                                                       |
| U1-R4  | 会话 cookie：`httpOnly` + `SameSite=Lax` + 生产 `Secure` + `Path=/`，值即 `sid`（32 字节随机）                                                     |
| U1-R5  | `requireAuth` / `requireAdmin` 中间件；在 `app.js` 的 9 个业务路由**之前**挂载                                                                      |
| U1-R6  | 端点：`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/session`、`POST /api/auth/change-password`、`PATCH /api/auth/profile` |
| U1-R7  | 管理端点：`GET /api/users`、`POST /api/users`、`PATCH /api/users/:id`、`POST /api/users/:id/password`（全部 `requireAdmin`）                     |
| U1-R8  | 登录失败限速：同 `ip + username` 连续失败 5 次锁 15 分钟（内存计数）                                                                                       |
| U1-R9  | 启动 seed：`users` 为空时创建 `admin/admin`，`mustChangePassword=true`                                                                        |
| U1-R10 | **CORS 收敛为白名单 + `credentials:true`**，与认证同批上线；生产未配 `CORS_ORIGINS` 时启动 fail-fast                                                       |
| U1-R11 | 登录、登出、改密、建号、重置、停用写入现有 `requestLogger` 审计线索（不新增日志系统）                                                                                  |

### 6.2 P0 — 交付单元 U2：前端登录与账户页（`client`）

| #     | 要求                                                        |
| ----- | --------------------------------------------------------- |
| U2-R1 | `/login` 页：用户名 + 密码 + 错误提示（不区分"用户不存在"与"密码错误"）             |
| U2-R2 | 会话 Provider（TanStack Query，`queryKey: ['session']`）+ 路由守卫 |
| U2-R3 | axios 响应拦截器：401 → 清缓存 → 跳登录（保留 `next`）                    |
| U2-R4 | `/account` 页：身份区块 + 改用户名 + 改密码 + 退出登录                     |
| U2-R5 | 强制改密态：进入账户页并锁死其它入口，显示说明文案                                 |
| U2-R6 | 侧栏底部：显示当前用户名 + 角色徽标；「退出登录」接真实 handler                     |

### 6.3 P0 — 交付单元 U3：管理员用户管理（`client`）

| #     | 要求                                                 |
| ----- | -------------------------------------------------- |
| U3-R1 | `/account/users`：用户表格（用户名 / 角色 / 状态 / 上次登录 / 创建时间） |
| U3-R2 | 新建用户表单（用户名、初始密码、角色），成功后提示"对方首次登录需改密"               |
| U3-R3 | 行内操作：停用/启用、重置密码、改角色                                |
| U3-R4 | 违反"至少一个启用 admin"时，操作按钮禁用 + 明确提示原因（不是静默失败）          |
| U3-R5 | 非 admin 访问该 Tab：不显示入口；直访 URL 显示 403 提示页            |

### 6.4 明确不做（与 §3 一致）

自助注册、多租户、找回密码、操作人留痕、角色细分、第三方登录、用户删除。

## 7. Acceptance Criteria

### U1

- [ ] 未带 cookie 请求 `GET /api/portfolios` → **401**（不是 200 空数组、不是 500）
- [ ] `POST /api/auth/login` 用 `admin/admin` → 200 + `Set-Cookie`，`mustChangePassword=true`
- [ ] 改密前的 `admin` 请求 `GET /api/portfolios` → **403** `PASSWORD_CHANGE_REQUIRED`
- [ ] 改密后同一 cookie 请求 → 200
- [ ] `member` 请求 `GET /api/users` → **403**；`admin` 请求 → 200
- [ ] 新建用户后，该用户首次登录被要求改密
- [ ] 停用某用户后，其已有 cookie 立即失效（下一次请求 401）
- [ ] 试图停用唯一 admin / 把唯一 admin 降级 → **400/409 + 明确错误码**，状态不变
- [ ] 连续 5 次错误密码 → 第 6 次即使密码正确也返回锁定错误
- [ ] 跨源请求（不在白名单）被 CORS 拒绝；`CORS_ORIGINS` 未配置时生产启动失败并给出明确错误
- [ ] `Server` 侧既有集成测试在改造后全绿（改造方式见 ExecPlan）
- [ ] 登出后 cookie 对应 session 在库中**被删除**（不是仅清前端）

### U2

- [ ] 未登录直访 `/portfolios` → 跳 `/login?next=/portfolios`，登录后回到原页
- [ ] 密码错误时提示文案**不泄露**用户名是否存在
- [ ] 改用户名后侧栏立即显示新名（无需刷新页面）
- [ ] 改密码后，另一个浏览器的同名会话在下一次请求时被登出
- [ ] 侧栏「退出登录」真实可用（点击后回到 `/login`，回退键无法回到已登录页面）

### U3

- [ ] admin 可见「系统设置」Tab，member 完全不可见
- [ ] 新建用户后可用该账号登录，且被判为需改密
- [ ] 唯一 admin 的「停用」「降级」按钮为禁用态，且有文字说明原因

## 8. 数据与安全要求（实现约束）

| 项     | 要求                                                 | 理由                                                     |
| ----- | -------------------------------------------------- | ------------------------------------------------------ |
| 密码存储  | `bcryptjs`，cost 10                                 | 纯 JS，无需本机编译（Windows 部署风险低）                             |
| 密码长度  | 8–72 字符；不强制复杂度规则                                   | 72 是 bcrypt 有效上限；强制复杂度对单家庭场景收益低、易致弱口令写纸条               |
| 用户名规则 | `^[a-z0-9][a-z0-9_.-]{2,31}$`，存小写                  | 避免大小写重复造成"看起来同名"的账号                                    |
| 唯一性   | `username` 建 unique 索引                             | 应用层校验 + DB 兜底                                          |
| 会话过期  | 绝对 7 天（TTL），`SESSION_TTL_DAYS` 可调                  | 简洁优先；不做滑动续期                                            |
| 会话存储  | MongoDB（`sessions` 集合）                             | 服务重启不掉线；且这是全仓**第一个 TTL**，正好补 `expireAfterSeconds` 缺失的债 |
| CSRF  | `SameSite=Lax` + 仅接受 `application/json`            | 覆盖浏览器场景；不引入 token 机制                                   |
| 传输    | 生产必须 TLS（`Secure` cookie 前提）                       | 见 `DEPLOYMENT §9`                                      |
| 审计    | 登录成功/失败、改密、建号、停用写 requestLogger；`User.lastLoginAt` | 不新建审计集合                                                |

## 11. Dependencies & Risks

### 依赖

- 无外部服务依赖；仅新增 npm 包（`bcryptjs`、`cookie-parser`）。
- 依赖 `server/app.js` 的单一挂载点（9 个业务路由集中注册）——已核实存在，认证可一处覆盖。

### 风险

| #  | 风险                  | 影响 | 处置                                                                     |
| -- | ------------------- | -- | ---------------------------------------------------------------------- |
| R1 | **U1 单独上线导致全站 401** | 高  | 发布约束：U1+U2 同批（§10）                                                     |
| R2 | **既有集成测试全部失效**      | 高  | 实测 **7 个测试文件**自起 HTTP 且用裸 `fetch`（见 Appendix A），需统一改造为"先登录再请求"的 helper |
| R3 | 用户忘记 admin 口令       | 中  | 运维兜底：`DEPLOYMENT` 记录"直接改库重置"步骤（需连 MongoDB）；不写进产品                       |

## 13. 产品设计（屏幕与状态）

> 本节为 §4 产品形态的**可视化落地**，供前端实现与走查对齐。可交互原型见 [`docs/ui/2.0/portomind-auth-prototype.html`](../../ui/2.0/portomind-auth-prototype.html)（单文件 HTML，含登录 / 账户 / 系统设置三屏与全部状态走查）。


### 13.1 信息架构与守卫

```
未登录 ──任意业务页──> 重定向 /login?next=<原路径>
/login（无 AppLayout：无侧栏/顶栏，居中卡片）
  └ 登录成功 → 若 mustChangePassword 则进入 /account（强制改密态）
               否则 → next 或 /account
/account（AppLayout：侧栏底部用户区进入，不占 5 个顶级导航位）
/account/users（仅 admin 可见入口「系统设置」；member 直访显示 403 屏）
已登录访问 /login → 重定向 /
任意接口 401 → 清缓存 → 跳 /login（保留 next）
```

### 13.2 三屏设计

| 屏 | 路由 | 关键元素 | 状态 |
|---|---|---|---|
| 登录 | `/login` | 用户名 + 密码 + 「登录」；统一错误「用户名或密码错误」；**不提示默认账号**（§4.1） | idle / 错误（不泄露账号是否存在）/ 加载 |
| 账户 | `/account` | 身份区块（用户名·角色徽标·状态·上次登录，只读）+ 改用户名 + 改密码 + 退出登录 | 正常 / **强制改密**（锁死其它入口，仅改密+登出可用）/ 改密后其他会话失效提示 |
| 系统设置 | `/account/users` | 用户表格（用户名/角色/状态/上次登录/创建时间/待改密）+ 新建 + 行内 重置密码·改角色·停用/启用 | admin 可见；member 403；唯一启用管理员行 停用/降级按钮禁用并提示原因 |

### 13.3 必须走通的交互状态（验收前必看）

1. **强制改密闸门**：`mustChangePassword=true` 时，除 `/account` + 登出外，访问 Dashboard/系统设置等一律被路由层拦截并展示「需先修改密码」屏（对应后端 403 `PASSWORD_CHANGE_REQUIRED`）。
2. **角色守卫**：`member` 无「系统设置」入口；直访 `/account/users` 显示 403 说明屏，不静默。
3. **至少一个启用管理员不变量**：当 `active && role='admin'` 仅剩 1 个时，其「停用」与「降级为成员」按钮禁用，hover/title 提示原因；管理员尝试停用自己也被拒（"不能停用自己"）。
4. **即时吊销**：停用 / 重置密码后，目标用户现存会话立即失效（原型以 Toast 提示"会话已失效"表达；实现层为 `Session.deleteMany({userId})`）。
5. **密码强度**：8–72 字符，不强制复杂度；改密需校验当前密码（管理员重置他人密码则无需当前密码，但目标账号置 `mustChangePassword=true`）。
6. **登录错误统一**：无论"用户不存在"还是"密码错误"，均显示同一文案，避免账号枚举。

### 13.4 与既有视觉语言一致

原型复用 `client/src/constants/design-tokens.js` 同源 token（主色 `#635BFF`、浅紫 `#EEEDFF`、边框 `#E3E8EE`、涨红 `#DF1B41`、跌绿 `#0E9F6E`、警示琥珀 `#F5A524`），与 2.0 全量原型（`docs/ui/2.0/portomind-prototype.html`）统一卡片 / 表单 / Modal / Toast 组件，侧栏用户区与「退出登录」真实接线。
