# 后续路线图

> 更新：2026-08-31。P2（CSV 导入）、P3（汇率换算/家庭视图）、P6（站内通知）已随批次 2/3 落地；以下为剩余远期项，逐项设计和验收，不建议同时开发。

## P1：登录和多用户

先建立 User、Portfolio 所有权和资源级授权，再开放公网访问。需要密码哈希或外部身份提供商、会话/Token 撤销、速率限制、审计日志和数据迁移。所有现有查询必须强制加入 `ownerId`，这是其他协作功能的前置条件。

## ~~P2：CSV 导入~~ ✅ 已实现（TR-09，2026-08-31）

采用「上传 → 字段映射预览 → 校验 → 幂等导入 → 错误报告」流程，支持天天基金/雪球列名识别，整批回滚。见使用指南 §4.3。

## ~~P3：汇率换算~~ ✅ 已实现（批次2，2026-08-31）

家庭视图以 RMB 折算（er-api 汇率 + 手动录入兜底），CNY/USD/CAD/HKD 分桶展示。注：当前折算采用**最新汇率**；「历史持仓用历史时点汇率重算」仍为远期（见 PRD §2 口径）。

## P4：移动端

优先完成响应式 Web：组合概览、交易录入、日志表格和图表触摸交互。指标是 360px 宽度无横向溢出、核心操作可用、表单键盘类型正确，再决定是否需要原生应用。

## P5：Docker

在运行模型稳定后提供前端、API、MongoDB 的 Compose 配置，加入健康检查、非 root 用户、只读镜像、持久卷、备份恢复和单一调度器所有权。密钥只通过运行时 secret/env 注入。

## P6：自动再平衡通知

~~站内通知~~ ✅ 已实现（提醒中心，2026-08-31）：再平衡触发写入 AlertEvent，Dashboard 通知中心可见。**邮件/Webhook 外部推送**仍为远期——需要去重、重试、投递状态、敏感信息最小化和用户退订。任何真正的自动交易都应作为独立的高风险项目重新评审。
