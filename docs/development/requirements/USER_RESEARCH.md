## 1. 研究背景与目标

### 1.1 背景

PortoMind 已完成六条价值线的功能建设（见 [PRODUCT_LINES.md](../../handbook/product/PRODUCT_LINES.md)），功能上「不缺」，

但处于典型节点：

> 功能完备度高于使用体验与产品认知——
>
> 即「有什么」很清楚，「谁在什么场景下为什么用它、还缺什么、哪些能删」尚缺一份系统回答。

### 1.2 研究目标

| # | 目标 | 对应产出 |
|---|---|---|
| 1 | 明确「谁在用、分成几类人、各自要什么」 | §3 用户分层与画像 |
| 2 | 把功能还原到真实场景，识别未被满足的 Job | §4 JTBD 与旅程 |
| 3 | 把「猜测的痛」变成「可验证的假设」 | §5 痛点假设清单 |
| 4 | 判断现有功能对用户的覆盖度与缺口 | §6 功能—需求映射 |
| 5 | 给出可执行的产品优先级 | §9 优先级排序 |
| 6 | 提供后续实证路径 | §10 验证计划 |

### 1.3 非目标

- 不做市场规模 / 商业化研究（产品明确「自托管、家庭自用」）。
- 不做视觉 / 交互可用性验收（另属设计验收范畴）。
- 不替代真实访谈与数据埋点。

| 维度 | 说明 |

| 方法 | 文档逆向分析（从 PRD / functions / USER_GUIDE 反推用户与场景）+ 假设构建 |

## 3. 目标用户

### 3.1 用户分层

`[假设]` PortoMind 的用户结构是「家庭内两人 + 一个技术角色兼任」，不是多租户 SaaS：

| 层级 | 角色 | 使用频率 | 深度 | 是否本次核心 |
|---|---|---|---|---|
| 核心 | 家庭投资主管 | 高频（周 / 日） | 重度（录入 / 决策） | **是** |
| 次要 | 家庭共同所有者 | 低频（月 / 季） | 轻度（查看 / 确认） | 是（影响设计） |
| 支撑 | 自持运维者 | 事件驱动 | 技术（部署 / 排障） | 是（决定可信度） |
| 外部 | 投资顾问 / 内容源（E大、有知有行） | — | 间接（提供信号） | 是（产品特色来源） |

### 3.2 画像 P1 — 家庭投资主管（核心用户）

| 维度 | 内容 |
|---|---|
| 代号 | `[假设]` P1「掌舵者」 |
| 身份 | 家庭中负责投资决策与记账的人；具备基础金融与工程能力，自建并维护本系统 |
| 目标 | ① 账本与真实账户一致；② 知道每个账户结构是否偏离目标；③ 偏离时得到可直接执行的调仓方案；④ 不错过关键时点 |
| 场景 | 月末对账补录、季度再平衡、收到外部建议后登记信号、日常看一眼通知 |
| 痛点 `[假设]` | 补录历史交易靠手输 / CSV；大类目标需要用但资产未分类；再平衡建议不能直接抄单（未取整）；估值分位数据要手工算再录 |
| 能力 | 熟练（能读 API、跑 CLI、查日志） |
| 成功定义 | 「我的账本从不骗我，且我知道下一步该做什么」 |

### 3.3 画像 P2 — 家庭共同所有者（次要用户）

| 维度 | 内容 |
|---|---|
| 代号 | `[假设]` P2「合伙看板」 |
| 身份 | 家庭另一位资产所有者；关心「一共有多少钱、最近怎么样」，不参与逐笔录入 |
| 目标 | ① 一屏看懂家庭总资产与币种分布；② 知道有没有需要自己确认 / 处理的事 |
| 场景 | 每月 / 每季度看一眼家庭视图；收到需要确认的事项 |
| 痛点 `[假设]` | 家庭层只有「当前快照」，没有趋势，看不出「比上个季度好还是差」 |
| 能力 | 新手–熟练之间；不接触 CLI |
| 成功定义 | 「我不需要问，就知道家里资产现在什么状况」 |

### 3.4 画像 P3 — 自持运维者（支撑用户，通常由 P1 兼任）

| 维度 | 内容 |
|---|---|
| 代号 | `[假设]` P3「守夜人」 |
| 目标 | ① 无人值守运行、不出静默故障；② 出问题时能快速定位 |
| 场景 | 部署 / 升级、价格同步失败排查、数据缺口补全、年度维护 |
| 痛点 `[假设]` | 完整性检查缺口超限时静默截断；节假日表 2027+ 需手工维护；双份调度实现导致行为不确定 |
| 成功定义 | 「我一个月不看它，它也在正确工作」 |

> **产品含义**：P3 的痛点会**以 P1 的体验形式外化**——数据质量问题最终表现为 P1 看到「—」、P2 看到「折算不完整」。因此 §9 中「数据质量」被计入产品优先级而非技术欠账。

### 4.2 场景地图（家庭双侧账户）

`[假设]` 基于产品定位（CN 侧 + CA 侧并行）的典型账户结构：

| 侧 | 真实账户 | 对应组合（accountType） | 记账币种 | 典型资产 |
|---|---|---|---|---|
| CN | 天天基金 | `tiantian` | CNY | 场外基金、A股宽基 ETF |
| CN | 雪球 | `xueqiu` | CNY | A股个股 / 场内 ETF、港股 |
| CA | TFSA | `tfsa` | CAD | 加股 ETF（如 XEQT 等） |
| CA | RRSP | `rrsp` | CAD | 加股 / 美股 ETF |
| CA | RESP | `resp` | CAD | 教育储蓄类资产 |
| 其他 | 应税账户 | `taxable` | USD / CAD | 美股 ETF |

**关键场景特征**：

同一家庭内存在 **3 种以上记账币种**、

**6+ 个真实账户**、

**5 个市场**（US / CA / CN-SH / CN-SZ / CN-Fund / HK）。

这决定了「家庭层折算」与「账户类型分组」是刚需而非锦上添花。

### 4.3 三条主旅程

#### 旅程 J1 — 月末对账与补录（服务 JTBD-1 / JTBD-7）

```text
打开系统 → 发现某组合持仓与券商不符
    ↓
导出券商/基金 CSV → 进入导入向导 → 列名自动映射 → 预览校验
    ↓
提交导入（失败整批回滚 / 重复自动跳过）
    ↓
核对持仓概览与成本 → 一致 → 完成对账
```

- 成功条件：账本与真实账户逐笔可解释。
- `[假设]` 断点：导入成功后发现某几行错，**没有「撤销该批次」**，只能逐笔删改。

#### 旅程 J2 — 季度再平衡（服务 JTBD-4）

```text
进入组合 → 阈值检查（偏离 5% / 10% 或超 60 天）
    ↓
输入可投入现金 + 费率假设 → 生成先卖后买清单
    ↓
查看双层饼图（当前 vs 执行后）→ 确认执行
    ↓
系统生成本地交易 → 持仓与比例更新
    ↓（后悔）
撤销 → 生成反向交易 → 重新生成建议
```

- 成功条件：一次操作即把组合拉回目标区间。
- `[假设]` 断点：清单未按整手 / 最小金额取整，**不能直接抄单**；建议项不能只执行一部分。

#### 旅程 J3 — 跟随外部信号（服务 JTBD-3）

```text
阅读 E大 / 有知有行 建议
    ↓
登记 signal 规则（方向 + 理由 + 有效期）
    ↓
有效期内 Dashboard 常显 → 到期自动归档
    ↓
执行买卖 → 录入交易 → 归档复盘
```

- 成功条件：外部建议被结构化留档，执行不遗漏、事后可复盘。
- `[假设]` 亮点：这是本产品**难以被通用理财 App 替代**的核心能力。

## 7. 竞品与替代方案

`[假设]` 用户当前 / 潜在替代方案（合规引用类型，不评价具体厂商优劣）：

| 替代方案 | 类属 | 优势 | 对本产品的短板 | PortoMind 相对价值 |
|---|---|---|---|---|
| 券商 / 基金 App（天天基金、雪球、券商客户端） | 交易工具 | 数据最准、可直接下单 | 单账户视角，跨账户 / 跨币种汇总弱；无统一成本法透明口径 | 跨账户统一记账 + 口径透明 |
| 通用理财聚合 App（海外类 Empower 等） | 聚合工具 | 自动对接账户、体验好 | 依赖授权、数据出境 / 隐私顾虑；不支持 E大 / 有知有行信号留档 | 自托管 + 隐私 + 信号留档 |
| 记账软件（MoneyWiz 等） | 记账工具 | 多币种记账成熟 | 无目标配置 / 再平衡 / 估值分位语义 | 投资语义专用 |
| 自建表格（Excel / Numbers） | DIY | 最灵活、零成本 | 无自动行情、无提醒、口径易错、难维护 | 自动化 + 可维护 |
| 有知有行 / 估值类工具 | 内容 + 工具 | 提供信号与估值 | 不负责家庭账本与再平衡执行 | 可与之互补（输入源） |

**差异化定位**：

PortoMind 的核心不可替代性 = **「自托管隐私」× 「跨账户多币种账本」× 「目标配置与再平衡闭环」× 「外部信号结构化留档」**。

其中最后一项与通用工具差距最大（§9 中列为差异化投入）。

## 8. 关键洞察

> 以下均为 `[假设]` 级洞察，需 §10 实证收敛。

**I1｜「可信账本」是全部价值的地基，录入体验 ROI 最高。**
再平衡、提醒、家庭总览的可信度，都受限于交易录入是否准确。而当前最痛的恰是录入的「批量维护」（H-01、H-09）。→ 强化导入可撤销与前端即时校验。

**I2｜再平衡的差异化已被「最后一公里」抵消。**
「先卖后买 + 费用模型 + 可撤销」已优于多数通用工具，但建议不可直接抄单（未取整 / 不可微调），用户仍需二次换算——差异化在最后一步流失。→ 取整 + 行内微调是**最高性价比**的投入。

**I3｜signal 规则是本产品最「用户独有」的能力，值得作为招牌强化。**
跟随 E大 / 有知有行的行为是核心用户的高频心智，通用工具无法承载。当前仅「登记 + 常显 + 过期归档」，可扩展「模板化登记 / 原文摘录 / 复盘视图」。→ 差异化投入重点。

**I4｜家庭层只服务「看」，未服务「共识」与「动」。**
P2 需要的是「趋势 + 结论」，而非「当前快照 + 一堆 null」。家庭层缺趋势曲线与家庭级目标，导致 P2 的 JTBD-5 只被部分满足。

**I5｜静默失败是信任的隐形杀手。**
缺价 / 缺汇率 / 未分类 / 无估值数据 / 缺口截断，全部以「—」或「不触发」静默呈现。用户无法区分「正常」与「坏了」。→ 建议确立**产品原则**：*任何降级都必须可见、可解释、可一键修复*（把业务口径文档 [CLIENT.md §5](../../handbook/manual/CLIENT.md) 的「宁可少报不可错报」从**算得对**升级为**说得清**）。

**I6｜数据质量应从「技术后台」上升为「面向 P1 的产品功能」。**
把完整性检查、同步状态、交易日历维护、汇率来源做成一个「数据健康」视图，直接回应 JTBD-7 与 P3 的痛点。

## 9. 需求优先级

### 9.1 Kano 分类（`[假设]`）

| 类别 | 需求 | 产品含义 |
|---|---|---|
| **必备型**（缺则强烈不满） | 账本准确（TR-04/05）、行情自动同步（AS-06）、到价 / 浮亏提醒（AL-02）、组合与目标配置（CM-01/06） | 先保稳，不投入即扣分 |
| **期望型**（越投入越满意） | 再平衡闭环（RB）、家庭总览（FAM）、CSV 导入（TR-09）、持仓/历史可视化 | 投入与满意度线性相关 |
| **兴奋型**（有则惊喜） | signal 跟随（AL-03）、估值分位规则（AL-10）、大类目标层（CM-08/RB-11）、数据健康视图 | 差异化来源 ← 应重点投入 |
| **无差异型**（做了浪费） | 组合类型细分（CM-03）、票据级 fee 拆分（TR-02） | 延后或不做 |
| **反向型**（做了扣分） | 自动交易、强制公网 / 多用户、过密推送 | 明确不做（写入非目标） |

### 9.2 轻量 RICE 排序（`[假设]`，用于同质需求比较）

> RICE = (Reach 触达 × Impact 影响 × Confidence 置信) ÷ Effort；
>
> Reach 用「受影响的核心 Job 数」替代真实用户量（因用户基数极小，采用相对值 1–5），Impact 3/2/1，Confidence 100%/80%/50%，Effort 以相对工作量计。
>
> **结果为相对排序，非绝对分值。**

| 需求 | Reach | Impact | Conf. | Effort | RICE | 排序 |
|---|---|---|---|---|---|---|
| RB-02/09 建议取整 + 可微调执行 | 5 | 3 | 0.8 | 2 | 6.0 | 1 |
| TR-09 导入批次可撤销 | 4 | 3 | 0.8 | 2 | 4.8 | 2 |
| AS-03/09 资产批量分类 | 4 | 2 | 0.8 | 2 | 3.2 | 3 |
| AL-10/AS-11 估值数据可得性 + 状态提示 | 3 | 3 | 0.8 | 2 | 3.6 | 4 |
| 数据健康视图（AS-07/AS-04/M0.1c） | 4 | 2 | 0.8 | 3 | 2.1 | 5 |
| FAM-01 家庭总资产趋势 | 3 | 2 | 0.8 | 2 | 2.4 | 6 |
| AL-08 规则模板 | 3 | 2 | 0.8 | 1 | 4.8 | — |
| CM-04 币种补 HKD | 2 | 2 | 1.0 | 1 | 4.0 | — |

> 说明：Effort 为相对量级（1 = 小，3 = 大），非人日承诺；Reach 采用「受影响 Job 数」的相对化处理，因此分值仅用于**同批比较排序**，不应跨批次直接相加。

### 9.3 汇总建议顺序

```text
先修底线（数据可信 / 安全 / 死代码清理）
  → 再补最后一公里（建议可取整可微调、导入可撤销）
    → 再让缺口可见（数据健康视图、估值状态提示、币种一致）
      → 最后做差异化强化（signal 深化、家庭趋势、规则模板）
```

（与 [PRODUCT_LINES.md](../../handbook/product/PRODUCT_LINES.md) §5 的三阶段路线图一致。）

## 10. 验证计划

本报告的假设需通过以下动作收敛（建议按顺序，成本从低到高）：

### 10.1 访谈提纲（对 P1 / P2，家庭内 1–2 人，半结构化）

1. 请回忆最近一次「录入交易」的完整过程，最烦的是哪一步？为什么？
2. 你有没有因为「分类太麻烦」而放弃使用某个功能？是哪个？
3. 拿到再平衡建议后，你是直接照着做，还是要自己再算一遍？算的是什么？
4. 打开家庭视图时，如果金额显示「—」，你第一反应是什么？你当时怎么处理的？
5. 你有没有出现过「以为某个提醒坏了」的情况？后来发现原因是什么？
6. 你现在怎么看「家庭资产比上个季度好还是差」？从哪看？
7. 如果明天要你教另一个家人用这个系统，你会先教哪三件事？
8. 有哪些功能你几乎没用过？当初为什么没继续用？

### 10.2 任务观察（可用性测试，5 个任务）

| # | 任务 | 观察指标 | 验证假设 |
|---|---|---|---|
| T1 | 从 CSV 导入 20 笔交易后，撤销其中一次导入 | 成功率 / 用时 | H-01 |
| T2 | 把组合从资产级目标切换到大类级并跑一次再平衡 | 是否因未分类受阻 | H-02 |
| T3 | 根据建议生成一份「可直接下单」的清单 | 是否需要人工换算 | H-03 |
| T4 | 新建「估值分位」提醒并让它生效 | 是否理解需先录数据 | H-04 |
| T5 | 在组合详情找到「平均成本」并解释含义 | 点击路径 / 是否困惑 | H-11 |

### 10.3 轻量埋点建议（若可加）

| 事件 | 目的 |
|---|---|
| 导入提交成功率 / 平均行数 | 度量 JTBD-1 真实负担 |
| 再平衡「生成建议 → 执行」的转化率 | 度量 JTBD-4 最后一公里流失 |
| 提醒规则创建后的首次触发率 | 度量 H-04「静默」严重度 |
| 家庭视图「—」出现频次与停留 | 度量 H-05 |
| 资产「未分类」占比 | 度量 H-02 |

### 10.4 收敛标准

- 每条 H-xx 更新为「已证实 / 已证伪 / 待定」并记录证据来源。
- §9 优先级表按实证结果重排一次。
- 将「已证实 + 高频 + 阻断闭环」的假设直接转为版本需求（接入 PRD 与路线图）。

## 11. 风险与限制

| 风险 | 影响 | 缓解 |
|---|---|---|
| 样本极小（1–2 人） | 结论普适性弱 | 明确定位为「单家庭自用产品」，不追求泛化 |
| 无真实用户数据 | 画像为假设 | 全部标注 `[假设]`，先验证再排期 |
| 产品团队视角偏差 | 只看到已建功能的用户 | 访谈中重点问「没用过的功能 / 放弃的功能」 |
| 隐私约束 | 访谈 / 埋点需谨慎 | 全本地、不采集敏感数据；截图需脱敏 |
| 假设被证伪 | 部分优先级失效 | 优先级表述为「可推翻」，以验证结果为准 |
