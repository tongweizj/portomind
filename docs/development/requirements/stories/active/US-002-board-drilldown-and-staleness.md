## 2. 用户问题与价值

**用户与场景：** 每天查看 PortoMind 的使用者。US-001 交付后，他打开日志频道就能看到五类任务谁标黄、谁标红——但他此刻只知道「有事」，还不知道「是哪件事、为什么」。

**当前问题：** 三处断点。
- 任务可能**根本没跑**（进程挂了、调度没触发），而运行态显示的不是 FAILED，也没有任何地方说「它该跑但没跑」。US-001 的僵尸识别只覆盖 `status=RUNNING` 且超阈值的情况，无法发现「压根没有新记录」。
- 再平衡分发只有一张聚合卡，写着「到期 2 / 生成 1 / 失败 1」。想知道**是哪个组合失败了、为什么**，没有入口——除非回去翻原始日志。
- 从一张标黄的卡片到它对应的原始任务日志，用户得自己记住任务名、切 tab、手动打日期。

**用户故事：** 作为每天检查数据的使用者，我希望从看板上任何一个异常都能一步追到具体原因（哪个组合、哪一天、哪条日志），并被告知「这个任务本该跑但没跑」，以便把「发现异常」直接变成「定位问题」。

**交付后的改善：** 异常卡片不再是一条死胡同。「没跑」有明确提示，「失败的是哪个组合」有独立可深链的页面，从卡片到日志是一次点击。用户判断「要不要处理、去哪处理」不必离开日志频道。

## 3. 本次范围与产品规则

### 本次交付

- **停滞提示**：任一任务「上次成功运行」距今超过「任务周期 + 缓冲」时，即使运行态不是 FAILED，也在卡片上提示「可能停滞」。
- **再平衡分发记录页 `/logs/rebalance`**：顶部汇总 + 四维筛选（日期 / 组合 / 状态 / 频率）+ 逐组合表格（组合 / 计划 / 到期 / 运行态 / 生成结果 / 建议数 / 失败原因 / 操作）；支持 `?date=` / `?portfolio=` / `?status=` / `?schedule=` 深链。
- **一键下钻**：卡片「查看日志」跳到任务日志 tab，并带上该任务与日期；再平衡分发记录页每行「查看原始日志」「去组合」。
- **数据契约未就绪时的显式降级**：父任务 `result` 缺失时页面顶部黄条 + 隐藏「到期 / 生成结果 / 建议数」三列，不得把「无记录」渲染成「未到期」或「正常」。

### 范围外事项

- 历史趋势图、launchDate 缺位治理引导（规格 P2 的 C-09 / C-10，不属本次）。
- 「再平衡提醒详情」（建议明细 + 执行 / 撤销 / 重做）——归组合域，由 US-003 承接；本 Story 的页面**只读**。
- 归档组合的再平衡分发记录（沿用既有 `archived` 语义，不额外设计）。
- 手动重跑 / 触发任务——运维语义，走 CLI 或 API，不进前端。

### 必要规则与约束

- **`/logs` 子树只读**：本 Story 新增与改动的任何页面**不得**出现执行、撤销、重做、手动触发、编辑阈值入口。这是规格 OQ6 的硬约束，需要可验证化（代码审查 + `grep` 无 mutation hook）。
- **频道子路由上限**：`/logs` 最多只允许 `/logs/rebalance` 这一条子路由。将来要加第二个详情页，须先评估是否独立成「系统健康」导航项。
- **「可能停滞」与「僵尸 RUNNING」不是一回事**：后者是 US-001 已交付的 `stale`（仅当 `status=RUNNING` 且 `startedAt` 超阈值）；前者是「上次成功运行距今超过周期 + 缓冲」，覆盖「进程没跑、连记录都没写」的场景。两者判定条件不同、文案不同，不得互相替代。
- **命名约束**：本页正式名称是「再平衡分发记录」，**禁止**叫「再平衡详情」——会与组合域的业务再平衡撞名。
- **降级不是完成**：C-05（US-001 的 TASK-057）未落地时本页可以显示，但只能算部分交付，不能据此宣称本 Story 完成。

## 4. 验收条件

| 编号 | 前提 / 场景 | 用户动作或触发事件 | 可观察的预期结果 |
|---|---|---|---|
| AC-01 | 某任务的上次成功运行距今已超过「该任务周期 + 缓冲」 | 打开任务运行看板 | 该卡显示「可能停滞」提示；正常任务不显示该提示 |
| AC-02 | 某任务从未运行过（无任何记录） | 打开看板 | 该卡显示无记录，**不**渲染成「正常」或「全部正常」；整体徽章不因无记录判为绿 |
| AC-03 | 某任务 `status=RUNNING` 且 `startedAt` 超阈值（僵尸） | 打开看板 | 显示为僵尸而非「正在运行」；与 AC-01 的「可能停滞」文案可区分 |
| AC-04 | 看板已加载，某卡标黄或标红 | 点击该卡「查看日志」 | 跳到任务日志 tab，且已带上该任务的筛选值与日期，无需手工再输入 |
| AC-05 | `GET /api/cron/status` 返回再平衡父任务 `result.perPortfolio[]` | 点击再平衡卡「查看详情」 | 路由变为 `/logs/rebalance`，面包屑可回到看板且返回后选择状态不丢 |
| AC-06 | 记录页已打开 | 使用四个筛选器（日期 / 组合 / 状态 / 频率） | 表格按筛选收敛，计数随之变化；筛选条件写进 URL，刷新后保持 |
| AC-07 | 直接访问带 `?portfolio=<pid>` 的深链 | 打开页面 | 组合筛选预置为该组合且刷新保持；非法 pid 回落「全部」并给出提示，不报错 |
| AC-08 | 某组合运行态为 FAILED | 查看该行 | 该行可辨识为失败，并展示失败原因（`failures[].category` 与 `message`） |
| AC-09 | 父任务 `result` 缺失（数据契约未就绪） | 打开记录页 | 顶部显示「数据契约未就绪」黄条，隐藏「到期 / 生成结果 / 建议数」三列；**不得**把「无记录」渲染成「未到期」或「正常」 |
| AC-10 | 所选日期无任何分发记录 | 打开记录页 | 显示「该日无再平衡分发记录」并说明两种可能（未到期 / worker 未运行），**不得**渲染为绿色「全部正常」 |
| AC-11 | 记录页渲染完成 | 检查页面 DOM 与代码 | 不存在执行、撤销、重做、重跑的控件；`/logs` 子树无任何 mutation hook 引用 |
| AC-12 | 某行有 `recordId` | 点击「去组合」 | 跳 `/portfolios/view/<pid>/rebalance?sub=history&record=<recordId>`；`recordId` 缺失时退 `?sub=suggestions` |
| AC-13 | 点击某行「查看原始日志」 | 触发跳转 | 落到任务日志 tab，任务名带该组合（`rebalance-suggestions:<pid>`）与日期 |
| AC-14 | 接口整体失败 | 打开记录页或点击刷新 | 显示局部错误态与重试入口，**不得**整页白屏，也不影响看板其他卡 |
