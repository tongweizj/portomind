## 0. 一句话结论

**结构全对，行为有 7 处会实现出错误产品。**

原型把已批准 IA 的**版面**（5 Tab / 目标 vs 实际 / 再平衡配置折叠区 / 健康表 / 分币种小计）都做出来了，1440×900 首屏折线也达标。但**行为层**存在一组「界面看起来正常、语义是错的」缺陷：

| 症状 | 后果 |
|---|---|
| 删除文案说反 | 用户以为交易记录会保留，实际被永久删除 |
| 「到期」态被吞 | 60 天没调仓的组合永远显示「配置正常」（实测确认） |
| 大类目标是假实现 | 用户设了 60% 股票类，保存那一刻系统就说"配置正常" |
| 待办点击被行覆盖 | 「2 条待确认」点下去落到总览，不是建议页（实测确认） |
| 子 Tab 内存态 / `?record=` 缺失 | US-4 可深链、US-7 精确落点两个故事在原型里 0 承载 |
| Header 读不存在的字段 | 落地照抄会重演 FS §1.4 那个"恒为暂无"的假数据位 |

一句话：**这批偏差的共同形态是"假成功"——不是缺功能，是给了错误的安全感。** 与本线立项动因（`USER_RESEARCH` I5：用户分不清「正常空态」和「坏了」）同源。

#### U-01 删除确认文案把级联范围说反

- **位置**：`:1487`
- **现状**：「此操作将删除组合 *X* 及其目标配置。**已有交易与事件不会级联删除**（口径见手册 §5）。」
- **事实**：`shared/services/portfolio/deletePortfolio.js:11-12` 明确 `Transaction.deleteMany` + `RebalanceRecord.deleteMany`（`AlertEvent` 不删）。文案把"删"说成"不删"。
- **应改为**：「将**同时永久删除**该组合的**全部交易记录与再平衡记录**，**不可恢复**。**该组合相关的提醒将不再显示**（事件数据保留、不随组合删除）。」第三句依 `OQ-E`（`HD-14`）裁决——「全部隐藏」而非「保留可见」，也不是物理删除。
- **依据**：FS `A9` 明文要求该文案；`HD-14` / `B16`；`R-4`（误删风险）；`AC13`。
- **验收**：DOM 内文案包含「永久删除」「交易记录」「再平衡记录」「不可恢复」四个要素，且含「提醒将不再显示」；不出现「不会级联删除」。

#### U-02 Header「最近再平衡」读一个不存在的字段，且空态用「暂无」

- **位置**：`:1458`（渲染）、`:576`（`daysSinceRebal`）、`:413/:419/:425/:2034`（mock 的 `lastRebal`）
- **现状**：`最近再平衡 · ${p.lastRebal || '暂无'}`。
- **事实**：模型 `shared/models/portfolio.js` **没有** `lastRebal`；真实字段是 `lastExecutedAt`（`summary.js:111` 已在算、未回传，FS `B1` 要求回传）。空态「暂无」违反 `AC15`（`grep` 不到「暂无」）。
- **应改为**：字段名统一 `lastExecutedAt`（`Date | null`）；有值渲染 `YYYY-MM-DD`（可加「(N 天前)」）；无值渲染「**从未**」。mock 数据一并改字段名。
- **依据**：FS `A10`、`AC15`；FS §1.4（"恒为暂无"的假数据位）。
- **验收**：全文件 0 处 `lastRebal`；0 处「暂无」用于再平衡空态；3 个组合（有值 / 60 天前 / 从未）各显一次。

#### U-03 再平衡子 Tab 是内存态，`?sub=` 在全文件出现 0 次

- **位置**：`:1632-1635`（`S.detail.rebTab`）、`:1552`（`S.detail.rebTab='hist'` 后跳转）
- **实测**（`_audit.cjs`）：
  - 点「再平衡历史」后 `location.hash` 仍是 `#/portfolios/view/cn-long/rebalance`；
  - `reload()` 后激活子 Tab 回到「再平衡建议」。
- **应改为**：`?sub=suggestions|history` 驱动；默认 `suggestions`；非法值回落默认。总览「查看历史 →」改为 `?sub=history`。
- **⚠️ 落地提示（必须写进原型注释）**：`route()`（`:683-697`）现在用 `h.split('/').filter(Boolean)` 切路径，**完全不处理 query**。`?sub=history` 会让 `parts[3]` 变成 `rebalance?sub=history` → 四个分支全部不命中 → 落到 `else`（交易记录）。**URL 化之前必须先给 `route()` 加 query 解析**，否则改完比现在更糟。
- **依据**：FS `A8`、`AC11`；US-4；FS §1.2（3 层不可深链）。
- **验收**：`?sub=history` 直开落在历史；刷新仍在历史；`?sub=xxx` 回落建议；`grep "rebTab"` 仅剩实现 URL 化所需的兼容代码或为 0。

#### U-04 `?record=` 精确落点整体缺失（A16 在原型里 0 承载）

- **位置**：`:469`（事件 `e1` 的 `link: '#/portfolios/view/cn-long/rebalance'`）
- **现状**：全文件 0 处 `record=`；历史表（`rebHist`）无高亮、无建议明细展开、无「不在最近记录中」提示。
- **应改为**（照 FS `A16` 三条）：
  1. 事件有 `snapshot.recordId` → `?sub=history&record=<id>`；无锚点维持 `?sub=suggestions`；
  2. 命中 → 该行高亮 + **自动展开只读建议明细**（`record.suggestions`）；`PENDING` 行尾追加「去处理」→ 切 `?sub=suggestions`；
  3. 未命中 → 「该建议不在最近记录中」，历史表照常渲染。
- **依据**：FS `A16`、`AC37/38/39`；US-7。数据已随 `getHistory` 返回，**零新增请求**。
- **验收**：带锚点的事件点击后 URL 含 `sub=history` 与 `record=<id>`；该行有高亮 class；展开行数 = `suggestions.length`；负向对照（无 `snapshot` 的事件）URL 不含 `record=`。

#### U-05 `driftOf` 把「到期未超阈」吞成「配置正常」

- **位置**：`:584`（`return { kind:'ok', ..., due:false }` —— 硬编码 `due:false`）
- **实测**（`_audit.cjs` 的 `dueOnly` 用例：阈值放宽到 100%、间隔 1 天）：
  ```json
  { "kind": "ok", "label": "配置正常", "due": false, "overN": 0 }
  ```
  即 **必然到期** 的组合被判为「配置正常」。
- **连带失真（同一根因，5 处）**：
  | 位置 | 现状 |
  |---|---|
  | `:1504` KPI「再平衡状态」第三分支 | 「配置正常 / 无待办」 |
  | `:1532` 目标 vs 实际卡头 | `d.overN ? ... : 配置正常` |
  | `:884` 组合列表卡徽标 | 「配置正常」 |
  | `:756` Dashboard 健康表 | 「配置正常」 |
  | `:1670-1676` 再平衡页 banner | 「当前配置在阈值内」 |
- **应改为**：`driftOf` 增加第四态 `due`（不超阈但已到期）：
  - `kind:'due'` → 文案「**已到期**（距上次再平衡 N 天 > 阈值 M 天）」；
  - 「正常」仅在**既未超阈、又未到期**时出现；
  - 另补「**从未执行**」态（`lastExecutedAt === null`）→ FS `A4` 的 `NEVER_EXECUTED` 文案，现原型完全没有。
- **口径必须先钉死（本卡定义）**：
  - 健康表/卡片里的 **N = 有 `triggeredThresholds` 非空的标的数**（`overThresholdCount`，OQ-A 裁决产物）；
  - 「已到期（N 天）」的 **N = 距上次再平衡天数**（不是逾期天数），文案带「未调仓」后缀消除歧义。
- **依据**：FS §4.1 四态表、`B8`、`AC26`、`G-1`；FS §1.5（时间维度不可见是本线立项理由之一）。
- **验收**：构造「间隔 1 天 / 阈值 100%」→ 全部 5 处显示「已到期」而非「配置正常」；构造「从未执行」→ 显示「从未执行过再平衡」；构造三态同时成立时以「超阈」优先。

#### U-06 大类目标是假实现：拿"当前实际占比"当目标

- **位置**：`:2085-2093`（`saveTargetForm` 的大类分支）
- **现状**：用户在大类模式填「股票类 60%」并保存 → 代码执行
  ```js
  p.holdings.forEach(h => { targets[h.sym] = 实际占比; });   // 注释：此处用市值结构保持不变（演示）
  ```
  丢掉了大类目标本身，把实际结构写成目标。
- **实测**（`_audit.cjs` 的 `classMode` 用例）：保存大类目标后 4 行 `abs` 全为 `0`、`flag` 全「正常」。
- **产品后果**：用户设定「股票 60%」，系统在**保存那一刻**宣布配置正常，且此后永远正常——这是全仓最危险的一类缺陷：**不是算错，是把判据换成了解**。
- **应改为**：保留 `level:'asset_class'` 语义；总览/建议按 `POST /rebalance/check` 的大类口径（FS `A15`），表格首列显示大类中文名。原型演示可用**固定摊分规则**（如按目标大类占比 × 类内当前结构），但**不得**用实际值冒充目标。
- **依据**：FS `A15`、§1.1；`checkThresholds` 已支持大类聚合（`thresholdChecker.js:78-102`）。
- **验收**：设「股票类 60% / 债券类 40%」+ 实际 80/20 → 目标 vs 实际表出现非零偏离并被判超阈；不得出现"保存即正常"。

### OQ-E｜删组合后残留提醒事件 —— **裁决：全部隐藏（`B16`）** ✅

- **事实**：`deletePortfolioCascade` 不删 `AlertEvent`（`deletePortfolio.js:11-12`）。删除后 Dashboard 事件卡仍带 `portfolioId`，点击跳 `/portfolios/view/<已删id>/...` → 404/白屏。
- **裁决口径（必须照此实现，别自由发挥）**：
  - **隐藏 ≠ 删除**：库里的事件原样保留（审计价值），只是**查询不可见**；

  - **资产级事件（`portfolioId = null`）必须保留**，否则会连带隐藏全局价格提醒。
- **被否掉的备选**：② 删除时把 `portfolioId` 置空（会把组合级事件伪装成资产级，污染语义）；③ 一并删事件（丢审计）。
