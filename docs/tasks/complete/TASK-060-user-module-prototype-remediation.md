## 0. 一句话结论

**骨架和权限语义都对，两处硬伤：一处违背已批 IA，一处是会让前端守卫走歪的死循环。**

auth 原型把 FS 的产品形态（三屏、两角色、强制改密闸门、至少一个启用 admin 不变量、即时吊销、只停用不删除、无自助注册）**全部做出来了**，14 条核对项过了 10 条，design token 与 `client/src/constants/design-tokens.js` 逐项同源（色值 / radii 6-8-10-pill / 侧栏 232 / 顶栏 64 / padding 24×32）。

但有两类问题：

| 症状 | 后果 |
|---|---|
| 侧栏被塞进「账户」「系统设置」两个顶级导航项 | 5 项变 7 项，直接违反 FS §4.4 / §4.5 的「不占顶级导航位」；导航位是本项目已确认的稀缺资源 |
| 未登录深链守卫把带 query 的 hash 当路径比对 | `next` 参数自我嵌套，`#/portfolios` 会打出无穷重定向；U2 的路由守卫若照抄即复现 |

一句话：**这不是"缺功能"，是"形似"。** A-01 会让信息架构在实施时静默漂移，A-02 会让深链回跳这个被写进 AC 的能力实际不可用。

#### A-02 未登录深链守卫自我嵌套，会打出无穷重定向

- **位置**：`:222`（`currentHash()`）、`:223`（`nextOf()`）、`:225-231`（`render()` 守卫）
- **现状**：
  ```js
  function currentHash(){return (location.hash||'#/login').replace(/^#/,'');}   // 返回含 query 的整串
  ...
  if(!state.session){
    if(h!=='/login'){ location.hash='#/login?next='+encodeURIComponent(h); }
    return renderLogin();
  }
  ```
- **实测推演**（手动改 URL 到 `#/portfolios`，未登录）：
  1. 第 1 轮 `h='/portfolios'` → 不匹配 `'/login'` → 写 `hash = '#/login?next=%2Fportfolios'`；
  2. `hashchange` 触发第 2 轮，`h='/login?next=%2Fportfolios'` → **仍不匹配 `'/login'`** → 写 `'#/login?next=%2Flogin%253Fnext%253D%252Fportfolios'`；
  3. 每轮 `next` 再套一层，**永不收敛**；同时 `nextOf()`（`:223`）取到的是嵌套后的垃圾串，回跳必然失效。
- **产品后果**：FS U2 的 AC「未登录直访 `/portfolios` → 跳 `/login?next=/portfolios`，登录后回到原页」在原型里**实际不成立**；前端若照此实现，401 拦截器（U2-R3）会继承同一缺陷——而 401 是所有页面共用的路径。
- **应改为**：
  1. 拆成 `currentPath()`（`h.split('?')[0]`）与 `currentQuery()`；守卫只比对 `currentPath() === '/login'`；
  2. `nextOf()` 只在 `currentPath()==='/login'` 时解析一次 `next`，且解析结果**必须**是内部路径（`startsWith('/')` 且不含 `next=`），否则回落默认；
  3. 写 hash 前先判：若已经是 `/login` 分支就不再改写（消除自触发）。
- **依据**：FS §4.5「未登录访问任何页面 → 重定向 `/login?next=<原路径>`；登录后回跳」；U2-R3；U2 AC 第 1 条。
- **验收**：模拟 `location.hash='#/portfolios'` → 稳定后 `hash` 恰为 `#/login?next=%2Fportfolios`（**`next=` 出现且仅出现 1 次**）；`hashchange` 不再自触发；`next=/portfolios` 登录后回到 `#/portfolios`；负向对照 `next=/login?next=x` 回落 `/`。
